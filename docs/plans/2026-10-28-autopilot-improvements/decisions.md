# Decisions: autopilot plugin improvements

Source of truth for every later agent. Cite by number.

1. **Plugin name.** Rename the plugin from `autopilot-forge` to `autopilot` (plugin.json, package.json, marketplace.json, all `autopilot-forge:` scoped agent names become `autopilot:`). Commands are then `/autopilot:<name>`. No alias.
2. **GitHub repo rename.** Permission granted to run `gh repo rename autopilot` on prithvijay-m/claude-code-forge and repoint `origin`, **at the end of the run** (ship step), together with updating every in-repo URL. Not before.
3. **Finish mode: `pr`.** New branch off main, pull request, CHANGELOG entry, version bump to 0.3.0. No merge to main by the pipeline.
4. **Persona scope.** Pilot voice in user-facing messages only: status lines, checkpoints, interventions, final report. Agent briefs, code, commits, PR bodies and ledger entries stay plain.
5. **Preview loop.** After the plan and before build, the planner writes a self-contained HTML clickthrough of the planned behaviour (mocked data); the main session publishes it as a private Artifact and runs the revise-and-republish loop with the user until they give the green light. Build never starts before that approval. The loop runs in the main session, not in an agent.
6. **Self-improvement.** Lessons keep auto-recording into the global store. A retro step detects repeated problems (same lesson twice, stalls, escalations) and writes a ready-to-apply patch under `docs/improvements/`; the user applies it with a command (`/autopilot:improve`). The pipeline never edits plugin files unprompted.
7. **Tech scout: on demand only.** No automatic scouting and no scheduled job. A `/autopilot:scout` command runs research agents that look for notable releases for the stack in use and list upgrades with install commands. Never auto-installs; alert only. (User chose this over the once-per-run default.)
8. **Copilots: the lead decides the cap.** A copilot is a conductor the main session dispatches for an independent sub-plan, each with its own ledger. No fixed ceiling chosen by the user; the lead decides from the host-load check and the task graph. DELEGATED to the planner: the sizing rule, and a backstop so a misjudgment cannot run away (the host-load headroom is the limit, not a constant).
9. **Commands shipped (all 15).** `/autopilot:` blueprint, build, intervention, merge, test, deploy, verify, status, agent, preview, scout, improve, recon, resume, copilot. Each is a thin `commands/<name>.md` entry that routes into an existing skill or agent.
10. **Auto-fix before pause.** On a detected stall, hallucination, circular reasoning or missing context, the conductor applies a remedy (reset with a trimmed brief, add missing context, escalate to senior, or split the task) and logs it. If the same task trips twice, the run pauses and notifies the user, exactly as a manual `/autopilot:intervention` does. DELEGATED to the planner: detector thresholds and the pause mechanism.
11. **Quality bar.** Tests first for every new script (`node:test`), CI green on ubuntu/macOS/Windows with Node 22 and 24, `tools/validate.mjs` extended for the new commands and the rename rules, portable paths only, plus a blind security review of the new commands and hooks (pause flag, auto-trigger).
12. **Limits.** 3 lanes, 8 hour limit, repo only: work stays inside /home/dev/src/claude-code-forge worktrees; nothing under /opt, no installs outside ~/.local, `~/.claude` read-only.
13. **Base branch.** Work on `feat/autopilot-0.3.0`, branched from `chore/release-0.2.2` (54a0c23); the PR targets main, so the 0.2.2 release rides along (0.2.2 to 0.3.0). The first commit carries the pipeline's `.gitignore` and `.graphifyignore` changes and the plan docs.
14. **Command meanings.** `merge` integrates lane and copilot branches into the integration branch, never main. `deploy` runs the target repo's documented deploy command only when the plan's contract names one, else says there is none. `agent` dispatches one named plugin agent with a brief. `test` runs the plan's gate. `intervention`, `preview`, `scout`, `improve`, `copilot` route to new skills or agents. Where a skill already owns the name (`blueprint`, `recon`, `verify`, `autopilot`), the skill is the command and no duplicate `commands/` file exists; `build` and `resume` route into the `autopilot` skill. `tools/validate.mjs` fails when a command name equals a skill name. `preview` falls back to writing the HTML file and printing its path when no Artifact tool exists.
15. **Copilots spawned by the lead conductor itself** (user kept this over the main-session-only default). Amends decision 8. The build's first task is a spike proving depth-2 nested dispatch works on this host; if it fails, the build stops and asks. Each copilot gets branch `autopilot/<slug>-cN` with a disjoint `Touches` set; a runner merges them into `autopilot/<slug>` before Finish.
16. **Mission unit = task.** "Mission N of M tasks completed": M is the plan's task count, N rises as each task merges. One terse pilot-voice line plus a 2-3 bullet summary per finished builder task, from the main session's checkpoint messages, plus `/autopilot:status` on demand. Line template pinned by a test.
17. **Demands-met check (DELEGATED, default accepted).** The user's request is stored verbatim in the plan dir at interview (`request.md`). After QA and before the PR, one reviewer in an ACCEPTANCE mode checks each request item and each decision against the branch with evidence. Unmet items go into the existing fix-once dispatch; still unmet is listed as "Not done" in the final report, never dropped.
18. **Name collision with the local autopilot (DELEGATED, default accepted).** Plugin run state moves to `.autopilot/runs/<plan>/` and the plugin never touches other files under `.autopilot/`. Auto-trigger stays opt-in via its existing override. README documents the clash with a same-named user skill.
19. **Rename edits are reviewed (DELEGATED, default accepted).** In-repo name and URL edits are normal build tasks, reviewed and validated (`validate.mjs` asserts no `autopilot-forge` or `claude-code-forge` string remains except in CHANGELOG history). Ship runs only `gh repo rename autopilot`, `git remote set-url origin`, then opens the PR. Amends decision 2's timing detail.

## Delegated decisions (planner)

New script files are written `scripts/{name.mjs}` in these plan docs: `npm run validate` fails on any doc that names a `scripts/` file before it exists, and the plan docs are committed before the build creates them.

20. Command routing: each `commands/<name>.md` hands `$ARGUMENTS` to one scoped target and never uses the plugin-root variable (whether the harness substitutes it in command bodies is unverified on this host). build and resume go to the autopilot skill; status, intervention, preview, scout, improve and copilot go to a new skill named cockpit (verb first); merge, test and deploy go to the runner agent with the procedure written in the command; agent goes to the named plugin agent. (delegated) One new skill keeps the session's skill listing short, a skill body does get the root substituted, and no command name equals a skill name (D14).
21. Cockpit layout: `skills/cockpit/SKILL.md` is a router that states the plugin root; each verb's procedure is a sibling file (INTERVENTION.md, IMPROVE.md, PREVIEW.md, SCOUT.md, COPILOT.md) read raw and written with `<scripts>` (ARCHITECTURE rule 3). (delegated) Siblings let separate tasks own separate procedures in parallel.
22. Pilot voice and mission line: one shared file `skills/autopilot/VOICE.md` holds the voice rules and the pinned line. The line is exactly `Mission <n> of <m> tasks completed.`, followed by 1 to 3 bullets (`- `, at most 100 characters each). n is the task's position in `RUN/missions.json`, which records integrated tasks in the order they were first reported (tasks first seen together are ordered lead ledger first, then copilots c1, c2, each in ledger order), so n only ever rises; lead and copilot ledgers count together; m is the number of task rows in plan.md. Bullets come from a ledger line `summary NN: <b1> | <b2> | <b3>` the conductor writes when it integrates a task, and fall back to the task's title. (delegated) D16 pins the template; reading bullets from the ledger keeps the message deterministic and costs no model tokens.
23. Run state (D18): "touch" means write, rename or delete. The plugin writes only under `.autopilot/runs/`: ledgers, cards, PAUSE, clock, and its rendered lessons at `.autopilot/runs/LESSONS.md`. `lessons.mjs sync` stops importing and copying a hand-kept `.autopilot/LESSONS.md` (the explicit `lessons.mjs import <file>` still does it). The guard still reads the user-authored `.autopilot/guard.json`. No fallback to 0.2.x ledger paths: a run started on 0.2.x finishes on 0.2.x, and CHANGELOG says so. (delegated) The local pipeline keeps a committed `.autopilot/LESSONS.md`; the guard rules file is the user's own config in either pipeline.
24. Host lane sizing (request item 1): host-load also reads cgroup v2 limits when present (`cpu.max` caps the cores, `memory.max` minus `memory.current` caps the free memory), keeps a reserve of max(1 GB, 10% of total memory) free for the OS and the session, and names the binding limit: `lanes: N of M (cores C, load L, free F of T GB, reserve R GB, bound by cpu|memory|plan)`. (delegated) On a VPS or in a container the OS numbers are host-wide; the cgroup is the real ceiling, and the reserve is what keeps the machine from swapping or killing processes.
25. Detector thresholds (D10): stall = a task's report arrives 90 minutes or more after its dispatch (twice the 45-minute task budget), or arrives with no verdict word; hallucination = a report cites a file path or commit SHA that does not resolve at the report's commit (one is enough); circular reasoning = the same task reports blocked twice with reasons at least 0.6 similar (the lessons similarity), or two consecutive fix rounds whose addressed count does not rise; missing context = a blocked reason matching `not found|missing|no such|cannot find|unknown|which file|where is`, or two or more `UNKNOWN:` lines in one report. Remedies: stall -> split when the task file has 8 or more acceptance criteria, else reset with a trimmed brief (task file and card only, no earlier output); hallucination -> reset with the unresolved citations as findings; circular -> escalate to senior; missing context -> re-dispatch with the missing paths and the graph card added. Each remedy is logged as `intervene: task NN <signal> -> <remedy>`. A task that already has an `intervene:` line and trips again pauses the run. (delegated) Deterministic, cheap, and keyed to the existing task budget.
26. Pause mechanism (D10): a flag file `.autopilot/runs/<plan>/PAUSE` whose first line is the reason (one line, control characters stripped, at most 200 characters), managed by a new pause script (`set`, `clear`, `show`). A PreToolUse hook on `Agent|Task` blocks (exit 2) a dispatch whose `subagent_type` is one of the build crew (conductor, coder, ux, db, reviewer, runner, senior, in scoped form) while any run in the repository has a PAUSE file; every other agent passes, so the session can still answer the user. The SessionStart status hint names a paused run. A blocked conductor ends its turn with `PAUSED: <reason>`, which the main session reports like a STOP. `/autopilot:resume` clears the flag, then builds. A pause never expires. (delegated) A file is visible to every process and hook, and blocking at the dispatch boundary pauses the run without killing work in flight.
27. Copilot sizing and backstop (D8, D15): a new copilots script splits the tasks not yet integrated into independent groups (no blocking edge and no shared Touches entry between groups). A group qualifies with 3 or more tasks. K = min(qualifying groups, host lanes); when K is below 2 there are no copilots and the lead builds as before. Otherwise every group goes to one of K crews (largest group first, into the crew with the fewest tasks so far), each crew to one copilot, and each copilot gets floor(host lanes / K) lanes, at least 1, so lanes summed over copilots never exceed the host-load reading. The lead dispatches all copilots in one message (they run side by side, like lanes), waits, re-dispatches any that return CHECKPOINT, then has a runner merge the `autopilot/<slug>-c<N>` branches into the integration branch in order, and runs Verify and Finish itself; copilots never run Verify, Finish or push. Backstop: (a) lanes summed over copilots never exceed the host-load reading taken at decision time; (b) each copilot re-asks host-load with its own share at every wave; (c) a copilot (its dispatch carries `COPILOT: c<N>`) never spawns copilots, and the script prints 0 when given `--copilot`; (d) the lead decides once, after Preflight, and on resume reuses the copilot ledgers that exist; (e) a copilot that fails to dispatch or returns without a verdict has its unintegrated tasks taken back by the lead, which builds them itself, as a ruling. Copilot branch `autopilot/<slug>-c<N>`, lanes `autopilot-lane/<slug>-c<N>/NN`, run directory `.autopilot/runs/<plan>-c<N>/`. (delegated) The host-load headroom is the only ceiling (D8), and no conductor can multiply itself.
28. Retro and improve (D6): a new retro script reads RUN/ledger.md and the lessons store and lists repeated problems: a lesson applying to this repository with count 2 or more, a task with 2 or more `intervene:` lines, any fix round 3 (senior escalation), any parked task. With at least one, it writes `docs/improvements/<YYYY-MM-DD>-<plan slug>.md` (Status: proposed; sections Problem, Evidence, Patch) in the built repository, uncommitted, after the pull request is pushed. The conductor then dispatches senior to write the Patch section as a unified diff against the plugin source (paths relative to the plugin root). A new improve script lists proposals, checks one (`git apply --check`) and applies it to a plugin checkout (`--root`, default the repository when its plugin.json is named `autopilot`). It refuses absolute paths, `..` segments, and paths outside agents/, commands/, docs/, hooks/, scripts/, skills/, tests/, tools/ and top-level `*.md`; it applies only with `--yes`; then it sets `Status: applied`. (delegated) Only the evidence can be deterministic; the patch needs a model; the user's command stays the only writer of plugin files (D6).
29. Scout (D7): a new agent `agents/scout.md` (Sonnet; tools WebSearch, WebFetch, Read, Grep, Glob only, so it has no shell and cannot install). The cockpit SCOUT.md procedure gets the stack tags from `lessons.mjs sync`, dispatches one scout per stack tag (at most 4, in one message), and prints one table: package or tool, version in use, latest release, why it matters, install command copied from upstream docs, source URL. Nothing is installed; each suggestion is checked against supermatt:dependency-vetting before it is shown. (delegated) D7: on demand, alert only.
30. ACCEPTANCE mode (D17): the reviewer's ACCEPTANCE mode takes request.md, decisions.md, BASE and HEAD, and gives every request item (each numbered line or sentence of request.md) and every decision number a verdict of MET, PARTIAL or NOT MET with evidence (file:line, test name or command output). The conductor runs it after QA and before Security; PARTIAL and NOT MET items join the fix-once dispatch; after the fix one ACCEPTANCE re-check covers those items only; what is still unmet goes under "Not done" in the pull request body and the final report. A plan with no request.md skips the step with a ruling. (delegated)
31. Rename check (D19): validate fails on `autopilot-forge` or `claude-code-forge` in any .md, .json, .mjs, .yml, .yaml or .html file except CHANGELOG.md and anything under docs/plans/ (historical records). validate.mjs and its test build both strings from parts, so neither file contains them. The checks that a named script, a scoped name and a link exist skip docs/plans/ and docs/improvements/, because plans and patch proposals name files that a build or a patch has yet to create. (delegated)
32. Spike shape (D15): the spike proves nesting three dispatch levels below the main session: the main-session conductor of this build (the /autopilot pipeline, not the plugin's agents/conductor.md) dispatches probe A (the plugin's own conductor agent), A dispatches probe B (the plugin's conductor again), and B dispatches probe C (general-purpose), which writes a nonce file the main session reads back. That is main session -> A -> B -> C, the depth main session -> lead conductor -> copilot -> builder needs. Probes A and B get a prompt that lifts the PLAN rules, so a missing PLAN is not a Stop; a probe `STOP:` about a missing PLAN is a probe defect, rerun once, not a FAIL. The result is recorded in `docs/spikes/nested-dispatch.md` as `RESULT: PASS` or `RESULT: FAIL`, with old names written `<old-name>` and the marker path `<marker>` (D19). On FAIL the build stops before task 20 and asks the user. (delegated)
33. Deploy field (D14): PLAN-FORMAT gains an optional Contract row `Deploy` (the repository's documented deploy command, or none). `/autopilot:deploy` runs it through the runner only when the row is present and not none, and otherwise says there is none. (delegated) D14 needs one named place for the command.
34. Merge and agent command limits (D11, D14): `/autopilot:merge` merges only lane branches `autopilot-lane/<slug>/*` and copilot branches `autopilot/<slug>-c<N>` into the plan's integration branch, and refuses when that branch is protected (main, master, trunk, production, prod, release). `/autopilot:agent` accepts only the names of this plugin's agents/*.md and passes the user's brief as the whole prompt. (delegated) Commands are prompt-injection surface.
35. Mission count across copilots: status aggregates the plan's own ledger and its `-c<N>` copilot ledgers, so a task integrated on a copilot branch counts as a completed mission. (delegated) D16 says N rises as each task merges, and copilot tasks merge into the copilot branch first.
36. Spike runner: the nested-dispatch spike is a step of the main-session conductor of this build (the /autopilot pipeline, which runs its own commands), not a builder task and not a step of the plugin's agents/conductor.md. (delegated) coder has disallowedTools: Agent, so no builder can dispatch; the step is a one-off for this build, so no task adds it to agents/conductor.md.
